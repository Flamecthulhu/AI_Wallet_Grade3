「什麼時候拿出什麼東西」
地點資訊 (Location Data)：
GPS_Lat, GPS_Lon：GPS 經緯度，代表當前位置。
WiFi_SSID_Count：周圍可偵測到的 Wi-Fi 基地台數量（可用於粗略判斷是否在室內或特定區域）。
Is_At_Train_Station：二元變數 (0/1)，判斷是否在火車站。
Is_At_HSR_Station：二元變數 (0/1)，判斷是否在高鐵站。
Is_At_School：二元變數 (0/1)，判斷是否在學校。
這些二元變數可以透過預先定義的地理圍籬 (geofencing) 結合 GPS/Wi-Fi 數據來判斷。
時間資訊 (Time Data)：
Hour_Of_Day：當前小時 (0-23)。
Minute_Of_Hour：當前分鐘 (0-59)。
Day_Of_Week：星期幾 (0-6)。
Time_To_Departure：距離最近一班預定出發時間的剩餘分鐘數。這個需要結合車票資訊來計算。如果沒有車票資訊，此值為 -1 或 0。
行程/車票資訊 (Trip/Ticket Data)：
Has_Paper_Ticket：二元變數，是否持有紙本車票 (0/1)。
Has_E_Ticket_QR：二元變數，是否持有電子票 QR Code (0/1)。
Has_EasyCard：二元變數，是否持有悠遊卡 (0/1)。
Has_Student_ID：二元變數，是否持有學生證 (0/1)。
Is_Ticket_Registered：二元變數，電子票/QR Code 是否已在設備上註冊 (0/1)。
Is_Entering_Station：二元變數，是否是準備進站 (0/1)。
Is_Exiting_Station：二元變數，是否是準備出站 (0/1)。
Is_Checking_In：二元變數，是否是準備報到 (0/1)。
Ticket_Scanned_Status：車票/卡片是否已經被掃描過（0: 未掃描, 1: 已掃描）。
環境/設備狀態 (Environment/Device Status)：
In_Scanning_Proximity：二元變數，是否靠近刷卡/刷票機 (0/1)。這可以透過近距離感應器、藍牙信標或視覺識別來判斷。
Device_Ready_For_Scan：二元變數，你的設備（如手機）是否已準備好進行掃描（例如 QR Code 已顯示在螢幕上）(0/1)。
Battery_Level：設備電量（如果你的「拿出」行為是透過手機顯示電子票，則電量可能是一個因素）。

    高鐵：車站代號, 設備代碼, 設備序號, 年份代號, 今年的第幾天, 此設備第幾張票
    台鐵：車種, 起站, 終點

1. 使用者習慣學習 / 模型預測
用簡單的機器學習（例如 Decision Tree 或 MLP）學習使用者的行為模式，例如：
每週一早上都會去學校 → 自動準備學生證。
平日早上都會刷某張悠遊卡 → 自動導通卡片。
Input feature 可用：GPS、時間、WiFi BSSID、行程記錄、使用頻率。

2. 票證有效性檢查
QR Code 或票卡在電子紙顯示前可先進行：
時間比對（未過期）->應該僅限高鐵
票種檢查（車種、起訖站匹配）
距離判斷（目前位置是否在附近）

3. 安全性機制（Anti-tampering）
QR Code 若涉及車票或票據資訊，建議加上：
加密（如 AES）或數位簽章（防止偽造）
使用一次性編碼 / 限時有效的 Token
顯示時加入防截圖特徵（如浮動圖層、水印）

4. 例外狀況處理
GPS 偏移、無 WiFi、時間模組失準，可能導致提前或錯誤顯示
解法：設排程手動刷新按鈕、加上備用操作提示

5. 節電與效能優化
電子紙只在必要時刷新，使用 timer / interrupt 觸發
NFC 線圈透過 MOSFET 控制通電時間，避免待機時漏電
